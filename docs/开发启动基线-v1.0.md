# mtide 项目开发启动基线 v1.0

> 状态：评审修订后可启动 P0/P1
>
> 日期：2026-11-03
>
> 本文把 `mtide-PRD-v2.0.md`（当前为 v2.2）与 `mtide-架构设计-v1.0.md` 转换为可执行的开发边界、阶段门禁和风险控制。它不是新的产品需求源；发生冲突时以 PRD 为准，并记录 ADR。

## 1. 开工结论

项目可以开始开发，但只能先启动 P0/P1。P2/P3 不是“顺手继续做”，必须在上一阶段出口验收通过后单独放行。

首个可交付目标是：在 Linux/macOS 上完成“打开工作区 → 编辑 → 保存 → 退出恢复”的无外部服务闭环，并证明渲染、输入、原子写、终端恢复和依赖方向可靠。LSP、DAP、AI、插件注册表和跨平台发布不属于 P0/P1 的启动前置实现。

## 2. 已锁定的技术边界

| 主题 | 开发约束 |
|---|---|
| 产品事实源 | `mtide-PRD-v2.0.md`（v2.2，170 条）；旧版 PRD 只作历史参考，不得新增需求 |
| 架构事实源 | `mtide-架构设计-v1.0.md`；跨 crate 新依赖必须先更新架构并写 ADR |
| UI 线程 | 可等待终端输入最多 8ms；不得做文件、网络、磁盘、子进程或 LSP/DAP/AI IO |
| 跨线程 | 通过命令/事件 channel 和不可变快照；不共享跨线程可变文档状态 |
| 写盘 | 所有宿主写盘经 `mtide-workspace`；临时文件同目录、flush/sync、rename、校验和 |
| AI 结构化模式 | 未通过 DiffGate、未校验基线 hash，不得写工作区 |
| AI 交互模式 | CLI 可自行读写；进入前明确告知；只做尽力而为变更追踪，不宣称完整审计 |
| 插件 | RPC broker 只约束宿主能力调用；普通插件进程不是 OS 沙箱，企业隔离需由外部策略完成 |
| 默认行为 | 不自动下载、安装、执行命令、联网或发送遥测；危险操作必须显式确认 |
| 依赖许可 | 仅接受 MIT/Apache-2.0/BSD/ISC/MPL-2.0；每次新增依赖记录体积、许可证和替代方案 |

## 3. 分阶段范围

### P0：骨架与质量门禁

实现 `mtide-api`、`mtide-proc` 最小骨架、`mtide-tui` 输入与 cell buffer、panic hook、CLI、workspace、`xtask check/depcheck/snapshot`。

出口必须满足：

- 空界面可在 80×24、120×40、200×60 渲染快照中稳定通过；
- 正常退出、panic、SIGINT 后终端 raw mode、光标和颜色状态均恢复；
- `cargo fmt --check`、`cargo clippy -- -D warnings`、单元测试、`depcheck` 全部通过；
- 依赖图符合 R-1～R-7，且 `mtide-workspace` 不反向依赖 L2 业务 crate；
- 所有失败路径有可分类错误，库代码不使用 `unwrap`、`expect`、`panic!`。

### P1：编辑闭环

实现 ED-01～ED-14、ED-21、UI-01～UI-06、UI-10、UI-19、UI-20、WS-01/02/04/05/07、SR-01，以及最小的 `mtide-syntax` 和 `mtide-search`。

出口必须满足：

- UTF-8、CJK、组合字符和 Emoji ZWJ 的光标、选区、行列转换有回归测试；
- 编辑操作具备原子性、撤销/重做、外部变更冲突提示；
- 配置、会话和快照写盘具备损坏检测，损坏文件不会阻断启动；
- 1 万行文件编辑和滚动按键 P95 ≤30ms；100 万行文件打开路径可取消且不阻塞输入；
- 至少一个真实工作区场景跑通：打开、编辑、保存、重启恢复。
- VSCode/VSCodium 常用键位在 Linux、macOS、Windows 的代表性终端中完成 A/B/C 兼容等级判定；终端截获键有诊断和替代键。
- 默认布局和 `File/Edit/Selection/View/Options/Help` 菜单树与 ttt 参考契约一致；主菜单、二级菜单、勾选项、焦点导航和 `Alt+Shift+M` 隐藏/恢复行为有快照与交互测试。

### P2：工作台闭环（单独放行）

实现 TR-01～TR-05、BD-01～BD-07、GT-01～GT-12、统一 diff、VT 状态机和终端面板。P2 的前置条件是 VT 网格测试、PTY 回收测试和 P1 性能门禁全部通过。

### P3：智能与扩展（单独放行）

按独立任务包推进 LSP、DAP、AI 结构化通道、AI 交互会话、导航/本地历史和插件宿主。AI-20 的验收必须接受“未知来源”，禁止使用“100% 识别 AI 改动”作为承诺。插件验收必须区分“broker 越权被拦截”和“普通进程 OS 访问不可拦截”。

## 4. 明确延期项

为避免 2–4 人团队在首个版本同时承担过多高风险系统，以下内容不进入 P0/P1，也不得作为隐含依赖：

- PL-11/PL-12 社区注册表和热重载；
- UI-16 图片预览、UI-18 Minimap；
- GT-13/GT-17/GT-18 PR 评审、Changelist、Shelve；
- BD-08 覆盖率展示、NV-12 结构化搜索；
- AI-13 多 CLI 对比、AI-14 全屏接管增强、AI-15 结构化 Agent 协议；
- WASM 插件运行时、在线更新、默认遥测和任何账号/云同步能力。

这些条目仍保留在 PRD 的路线图中，但没有进入当前开发分支的完成定义。

## 6. 每个任务的完成定义

每个任务卡必须包含 PRD 编号、失败测试、实现、回归测试、风险说明和回滚方式。以下任一项未完成，不得标记 Done：

1. 新增行为有至少一个可读的验收测试；
2. 取消、超时、断管、权限拒绝和外部修改等失败路径有测试；
3. 没有引入未登记的跨 crate 依赖、同步 IO 或自动化外部副作用；
4. 文档、协议版本和配置示例已同步；
5. `cargo xtask check`（命令存在前，等价门禁逐项执行）全绿。

## 7. 首批任务顺序

1. T-00：建立 workspace、crate 空壳、依赖检查和 CI 门禁；
2. T-02：完成子进程 RAII、超时、取消和孤儿回收；
3. T-03：完成类型化坐标和文档编辑原子性；
4. T-01/T-04：完成 cell buffer、差量渲染、布局与焦点；
5. T-06：完成配置、快照、原子写和文件监听；
6. T-07/T-08：接入基础语法高亮和搜索；
7. 通过 P0/P1 出口评审后，再进入 VT、终端、任务和 Git。

## 8. 开发前仍需 ADR 的事项

- ADR：文件监听丢事件与“未知来源”变更的用户交互；
- ADR：插件 broker 权限模型与企业 OS 沙箱的责任边界；
- ADR：快照 sync/rename 在 Windows 和网络文件系统上的降级策略；
- ADR：遥测/崩溃上报的 opt-in、数据字段和隐私声明；
- ADR：2 人团队时 P2/P3 的裁剪方案。

## 9. 发布前不可绕过的红线

- 未确认的 AI 结构化补丁不得改变文件 hash；
- 交互会话不得对外宣称“IDE 审核了 AI 的所有操作”；
- 插件不得对外宣称“进程隔离即安全沙箱”；
- 首屏不得等待 LSP、Git、插件索引、网络或 AI 探测；
- 默认关闭的网络、安装、遥测和外发能力不得被配置样例意外打开。
